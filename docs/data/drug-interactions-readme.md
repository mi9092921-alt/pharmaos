# قاعدة تداخلات دوائية أولية — مطابقة على الكود الفعلي

**الملف:** [drug-interactions-seed.sql](./drug-interactions-seed.sql) — بيانات مرجعية **جاهزة للتبني** (ليست ترحيلًا نشطًا؛ لم يتغير أي شيء في قاعدة البيانات حتى الآن).

> **⚡ قراءة إلزامية قبل التبني:** القرار التقني الموثق بعد مراجعة خارجية — [../drug-interactions-technical-decision-ar.md](../drug-interactions-technical-decision-ar.md). أهم ما يغيّر هذا الملف عند التبني: طبقة هوية المواد (`medication → medication_ingredients → ddi_ingredients`)، وفصل `source_severity` / `normalized_severity` / `severity_mapping_version`، والمطابقة على `ingredient_id` لا الاسم النصي، وحالات الفحص الأربع (ممنوع المساواة بين غياب البيانات والسلامة). هذا الملف يظل دقيقًا كوصف للبيانات؛ بنية الاستخدام النهائية تتبع القرار التقني.

## على أي أساس بُنيت؟ (من الكود الفعلي)

| الاعتماد           | من أين في الكود                                                                                                           |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| مصدر المطابقة      | `medications.scientific_name` (VARCHAR 255) — `supabase/migrations/20260711000300_catalog_schema.sql:81`                  |
| توحيد النص العربي  | دالة `normalize_arabic()` الموجودة نفسها في المخطط (توحيد أ/إ/آ→ا، ة→ه، حذف التشكيل والتطويل)                             |
| أسلوب البيانات     | أسماء علمية عربية كما في `tools/dev-seed/seed_demo_catalog.py` ("باراسيتامول"، "ديكلوفيناك"…)                             |
| نمط المخطط         | أعمدة `is_deleted / sync_version / created_at / updated_at` مثل بقية جداول الكتالوج                                       |
| الحاجة إلى حقل ATC | **غير مطلوبة** للفحص الأساسي — الأزواج مقفلة على المواد، والتكرار (نفس الفئة) يعالج لاحقًا عبر `drug_class` الموجود أصلًا |

## كيف تعمل المطابقة؟

1. كل مفتاح في البيانات = **كلمة عربية واحدة بعد التطبيع** (مثال: `ايبوبروفين` — بلا همزة، لأن `normalize_arabic` يحول أ→ا).
2. دالة الفحص `check_drug_interactions(ARRAY['...'])` تستقبل أسماء خام **كما هي** من `scientific_name` (مع جرعات، معهمزات، بتركيبات "أ + ب")، تُجزّئها إلى كلمات، تُطبّعها، تزيل بادئة "ال"، ثم تقاطعها مع القاموس.
3. الأزواج إما **مادة × مادة** أو **مادة × فئة** (nsaid، macrolide، ssri…) — بحيث يغطي زوج واحد عشرات الأدوية التجارية.

```sql
-- مثال: بعد تأكيد الصيدلي لسطور الوصفة/الفاتورة
SELECT * FROM check_drug_interactions_by_ids(ARRAY['<uuid1>'::uuid, '<uuid2>'::uuid]);
```

## حجم البيانات الحالية

- **~95 مادة فعالة** شائعة في الصيدليات المصرية/العربية (مع تنبيهات فردية مثل: أسبرين والأطفال/متلازمة راي، ميترونيدازول والكحول، إيزوتريتينوين والحمل).
- **19 فئة دوائية** لتجميع الأزواج.
- **~80 زوج تداخل** بشدة major/moderate وآلية وإجراء مبسطين بالعربية، مستخرجة من معلومات عامة منشورة (نشرات FDA، قائمة ONCHigh الأمريكية عالية الخطورة، ومصادر أكاديمية مفتوحة).

## التبني (عندما تقرر)

1. انسخ محتوى `drug-interactions-seed.sql` إلى `supabase/migrations/2026MMDDNNNNNN_drug_interactions.sql`.
2. شغّل الترحيلات كالمعتاد.
3. خيار الدمج في نقطة البيع لاحقًا: عند اكتمال سلة الفاتورة → استدعاء `check_drug_interactions_by_ids` → عرض بطاقات التنبيه (شدة + آلية + **خيارات الصرف: صرف بمبرر / اتصال بالطبيب / إلغاء**) → تسجيل القرار في سجل التدقيق.

## حدود يجب فهمها (بلغة صريحة)

- **بيانات أولية (starter):** تغطي الشائع عالي الخطورة فقط؛ ليست بديلًا عن Micromedex/Lexicomp. مراجعة **صيدلي مختص** شرط قبل الاعتماد الإنتاجي.
- **مطابقة بالمفردات:** أسماء علمية مكتوبة بصيغ غير متوقعة قد لا تُضبط (مثل "آسبرين" بحرف مختلف — التطبيع يعالج أشيع الحالات). يُنصح بتشغيل استعلام تدقيق على المخزون الحقيقي بعد التبني: `SELECT id, trade_name, scientific_name FROM medications WHERE normalize_arabic(scientific_name) NOT IN (SELECT key FROM ddi_ingredients);` لرصد الأصناف غير المغطاة.
- **الأزواج الخاصة قد تتكرر مع فئتها** (مثل كلاريثروميسين×وارفارين major + ماكروليدات×وارفارين moderate): عند بناء الواجهة تُعرض الأدقّ (major) وتُكتم الأعم — قرار واجهة، لا بيانات.
- **المبدأ الثابت:** النظام يُنذر ولا يقرر — كل تنبيه يمر بإقرار الصيدلي ويسجل في السجل.
