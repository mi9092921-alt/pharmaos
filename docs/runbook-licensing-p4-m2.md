# PharmaOS — دليل تشغيل التراخيص (Runbook P4-M2)

> **المجال:** إدارة دورة حياة التراخيص، إصدار المفاتيح، التفعيل، والتعافي من حالات الفقدان والتلاعب.  
> **المستوى:** مالك النظام / مسؤول الدعم الفني (Vendor Operations & Device Support).

---

## 1. المفاهيم الأساسية وهيكل الحماية

يعتمد نظام PharmaOS على نموذج ترخيص محلي بدون اتصال بالإنترنت (Offline-First Licensing) يعتمد على:

1. **مفتاح الإصدار (Issuer Key):** مفتاح غير متماثل من نوع Ed25519 مشفر ومحمي بكلمة مرور. يُحفظ **فقط** على جهاز المالك (`~/.pharmaos-vendor/` أو مجلد آمن منفصل).
2. **المفتاح العام المدمج (Baked Public Key):** مدمج في الكود المصدري للـ API (`apps/api/src/pharmaos_api/licensing/vendor_key.py`) ولا يمكن استبداله إلا بتحديث برمجي.
3. **معرف العتاد (Hardware ID - HWID):** بصمة فريدة للجهاز بصيغة `PHAR-XXXX-XXXX-XXXX-XXXX` يتم حسابها من عتاد الجهاز (BIOS UUID، معالج، لوحة أم).
4. **سلسلة سلامة الوقت (Time-integrity Chain):** سجل أحداث مشفر بـ HMAC ومخزن في قاعدة البيانات ومنافذ تخزين خارجية (ProgramData + Windows Registry) لمنع التلاعب بساعة النظام.

---

## 2. الخطوة الأولى: توليد مفتاح المالك (مرة واحدة فقط)

يتم توليد زوج المفاتيح مرة واحدة فقط عند إعداد بيئة المالك:

```powershell
# تعيين كلمة المرور عبر متغير بيئة أو إدخالها عند الطلب
$env:PHARMAOS_LICENSE_PASSPHRASE = "StrongPassphraseHere"

# تشغيل أداة الترخيص
python -m pharmaos_license_cli.cli --key-file .pharmaos-devkeys/issuer.plkey init
```

### المخرجات المتوقعة:

- ملف المفتاح المشفر: `.pharmaos-devkeys/issuer.plkey` (تنسيق PLKEY1 الثنائي، محمي بـ Scrypt + AES-256-GCM).
- معرف المفتاح: `kid` (مثال: `4ff86fbe`).
- المفتاح العام بصيغة PEM: يتم دمجه في `vendor_key.py`.

> [!CAUTION] > **تحذير أمني حرج:**  
> ملف المفتاح الخاص (`.plkey`) وكلمة مروره لا يجب رفعهما إطلاقاً لأي مستودع git أو إرسالهما لجهاز العميل.  
> احتفظ بنسخة احتياطية مشفرة على وحدة تخزين خارجية منفصلة (Cold Storage / USB).

## 3. إصدار ملف ترخيص لجهاز عميل جديد

عند تثبيت النظام لأول مرة على جهاز العميل، يقلع النظام في حالة **`unlicensed`**.  
تظهر شاشة التفعيل للعميل وتعرض معرف العتاد الخاص به (HWID)، مثل:  
`PHAR-8F2B-93A1-C4E0-1122`

يقوم المالك بإصدار الترخيص من جهازه:

```powershell
python -m pharmaos_license_cli.cli --key-file .pharmaos-devkeys/issuer.plkey issue `
  --customer "صيدلية النور - فرع 1" `
  --hwid "PHAR-8F2B-93A1-C4E0-1122" `
  --preset annual `
  --out "pharmacy-alnoor.license"
```

### الخيارات المتاحة للمدد الزمنية (`--preset`):

- `trial`: تجريبي لمدة 14 يوماً.
- `monthly`: شهري لمدة 31 يوماً.
- `annual`: سنوي لمدة 365 يوماً.
- `emergency`: ترخيص طوارئ لمدة 7 أيام.
- `--months N`: مدة مخصصة بعدد الأشهر (30 يوماً لكل شهر).

## 4. التحقق من ملف الترخيص قبل تسليمه للعميل

للتحقق من سلامة وصلاحية الملف الذي تم إصداره:

```powershell
python -m pharmaos_license_cli.cli verify --file "pharmacy-alnoor.license"
```

## 5. تفعيل الترخيص على جهاز العميل

يمكن تفعيل الترخيص بإحدى طريقتين:

### أ) عبر واجهة المستخدم (Web UI / Electron):

- من شاشة التفعيل (`/activate`)، يقوم المستخدم باختيار أو سحب ملف `.license`.

### ب) عبر الـ API مباشرة:

```bash
curl -X POST "http://127.0.0.1:8000/api/v1/license/activate" \
  -H "Content-Type: application/octet-stream" \
  --data-binary "@pharmacy-alnoor.license"
```

### الرد المتوقع عند النجاح (HTTP 200):

```json
{
  "success": true,
  "data": {
    "status": "active",
    "hwid": "PHAR-8F2B-93A1-C4E0-1122",
    "valid_until": "2027-10-09T13:00:00Z",
    "days_left": 365,
    "needs_activation": false
  }
}
```

## 6. حالات الترخيص وسلوك الـ API (Status Matrix)

| الحالة (`status`) | كود الخطأ   | رمز HTTP | سلوك الـ API                                                                                                   |
| ----------------- | ----------- | -------- | -------------------------------------------------------------------------------------------------------------- |
| **`unlicensed`**  | `E-LIC-001` | `403`    | يُسمح فقط بـ `/health` و `/license/status` و `/license/activate`                                               |
| **`active`**      | -           | `200`    | تشغيل كامل لكافة العمليات والصلاحيات                                                                           |
| **`grace`**       | -           | `200`    | فترة سماح 30 يوماً بعد انتهاء الاشتراك — تشغيل كامل مع تنبيه التجديد                                           |
| **`read_only`**   | `E-LIC-002` | `403`    | بعد انقضاء السماح: حظر كافة عمليات التعديل والإضافة (POST/PUT/DELETE) مع السماح بالقراءة و `/license/activate` |
| **`tamper`**      | `E-LIC-006` | `423`    | إغلاق مقفل بالكامل نتيجة اكتشاف تلاعب بساعة النظام أو سجل الأحداث                                              |
| **`key_lost`**    | `E-LIC-008` | `423`    | مفتاح HMAC مفقود من الـ Keystore الخاص بالجهاز                                                                 |
| **`error`**       | `E-LIC-007` | `503`    | تعذر فحص حالة الترخيص مؤقتاً                                                                                   |

## 7. سيناريوهات الدعم الفني والتعافي

### سيناريو 1: حالة فقدان المفتاح (`key_lost` — E-LIC-008)

- **السبب:** مسح بيانات التخزين الآمن لنظام التشغيل (Windows Credential Manager / DPAPI)، أو تشغيل البرنامج من مستخدم Windows آخر غير الذي تم تثبيت وتفعيل البرنامج عليه (عزل HKCU).
- **الحل:**
  1. التأكد أولاً من تسجيل الدخول بنفس مستخدم Windows الأصلي.
  2. إذا كان المفتاح قد فُقد فعلياً، يقوم المالك بإصدار ترخيص جديد للجهاز بتاريخ إصدار حديث (`issued_at` أحدث من آخر قيد مسجل في السلسلة).
  3. تفعيل الملف الجديد عبر `POST /api/v1/license/activate` يقوم بتوليد مفتاح HMAC جديد تلقائياً وإعادة ختم السلسلة (Re-seal).

### سيناريو 2: اكتشاف تلاعب بساعة الجهاز (`tamper` أو `clock_error` — E-LIC-006)

- **السبب:** إرجاع ساعة الجهاز للوراء بأكثر من 6 ساعات في محاولة لتجاوز تاريخ انتهاء الترخيص.
- **الحل:**
  1. تصحيح تاريخ ووقت النظام ومزامنته عبر الإنترنت (NTP).
  2. إصدار وتفعيل ترخيص جديد حديث معتمد من المالك لتجاوز نافذة السلسلة السابقة.

### سيناريو 3: استعادة نسخة احتياطية (Real Restore vs Import-Keys)

- عند استعادة قاعدة بيانات كاملة على جهاز مختلف:
  - تفشل المصادقة بسبب اختلاف الـ HWID (`E-LIC-004`).
  - يجب إصدار ترخيص مخصص للـ HWID الخاص بالجهاز الجديد.
